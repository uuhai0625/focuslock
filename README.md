# FocusLock(Chrome拡張機能)

サイトブロック・フォーカス支援ツール。市場調査・評価基準の緩和議論の詳細は`kuro/`の自動メモリ`project_chrome_extension_business.md`を参照。

## ポジショニング(重要な設計方針)

市場調査で「Freedomの中核価値(全端末での強制ブロック・拡張機能自体のアンインストール防止)はブラウザ拡張機能の権限モデル上、原理的に再現不可能」と判明している。**この拡張機能は「Freedomの代替」を謳わない。** 「無料のサイトブロック拡張機能(BlockSite等)より一段強い、衝動的な解除を防ぐ摩擦を持たせた、単体デバイス・買い切り型のフォーカスツール」という限定した訴求に絞る。ストア説明文にも「拡張機能自体を無効化・削除すればブロックは解除される」ことを正直に明記する方針。

## 機能

- **今すぐブロック(無料)**: 手動でON/OFFを切り替えるシンプルなサイトブロック(BlockSite等の無料版相当)
- **集中セッション(買い切り版)**: 25/50/90分のタイマーを設定し、その間はブロック対象サイトを開けなくする。セッション中に「早く終了する」を押すには、事前に設定した合言葉の入力が必要(StayFocusdの「長い文言を打たせる」方式を踏襲、ただし合言葉は自分で自由に設定できる点で差別化)
- **スケジュール(買い切り版)**: 曜日・時間帯を指定し、セッションを開始しなくても自動でブロックする(例: 平日9-17時はSNSを自動ブロック)
- **統計**: 完了したセッション数・合計フォーカス時間

## 技術構成・アーキテクチャ上の注意点

- Manifest V3。ブロックは`chrome.declarativeNetRequest`の動的ルール(`updateDynamicRules`)で実装。`action.type: "redirect"`で`blocked.html`(拡張機能内ページ)へリダイレクトする方式。
- **`host_permissions: ["<all_urls>"]`が必須。** SnapFolioは`activeTab`+`scripting`まで絞り込めたが、本拡張は「ユーザーが操作していないタブ・サイトへのアクセスも継続的にブロックする」ことが機能の本質のため、`declarativeNetRequest`の`redirect`アクションに広範なホスト権限が要る(プレーンな`declarativeNetRequest`権限は`allow`/`block`のみの暗黙付与で、`redirect`には`host_permissions`または`declarativeNetRequestWithHostAccess`が必須、というChrome公式ドキュメントの仕様)。Chrome Web Store申請時に審査が長引く可能性がある点は事前に認識しておくこと。
- urlFilterはAdblock Plus由来の`||domain^`構文(ドメインアンカー、`chrome.declarativeNetRequest`が公式サポート)を使用。`lib/patterns.js`でユーザー入力からドメインを抽出して生成。
- **storageとdeclarativeNetRequestを読み書きする処理は全て`background.js`内の`enqueue()`キューで直列実行する。** 並行実行を許すとread-modify-writeが競合し、片方の更新が消えたりルールが古いスナップショットで上書きされたりする(SnapFolioの`captureQueue`と同じ設計思想)。`ADD_SITE`/`REMOVE_SITE`/`SET_MANUAL_BLOCK`/`SET_SCHEDULE`/`START_SESSION`/`finishSession`は全てこのキューを通す。
- サイトの識別子は`Date.now()`ではなく永続化した連番カウンタ(`lib/storage.js`の`allocateId`)を使用。`declarativeNetRequest`のルールIDは小さな正の整数である必要があり、タイムスタンプをそのまま(または雑にハッシュして)使うと衝突しうるため。
- スケジュールの日またぎ判定(例: 22:00〜翌6:00)は、「当日の夜」だけでなく「前日から続く早朝」も判定に含める。日付が変わった瞬間に`rule.days`が前日のままだと誤ってブロックが解除される問題があったため。
- セッションの「早く終了する」ロックは合言葉方式。合言葉が未設定の場合はロックが機能しない設計(意図的な仕様として明記)。
- `chrome.alarms`でセッション終了・毎分のスケジュールチェックを実装。ブラウザ再起動時(`onStartup`)、セッションが既に終了時刻を過ぎていれば自動的に片付ける。

## 独立エージェントによるコードレビュー(2026-08-29実施・反映済み)

PromptDiff/SnapFolioと同じく、実装後に独立エージェント8方向(正しさ3+クリーンアップ3+altitude+conventions)でコードレビューを実施し、以下を修正済み:

- **`host_permissions`が未宣言でブロック機能自体が動作しない(最重要)**: `declarativeNetRequest`のプレーン権限は`redirect`アクションに必要な範囲を暗黙付与しない。`host_permissions: ["<all_urls>"]`を追加
- **サイトIDのハッシュ衝突でルール同期が壊れる**: `Date.now()`ベースのIDをmod計算していたため15分の倍数差で衝突しうる問題。永続連番カウンタに変更
- **カウントダウン表示がpopupとblocked.htmlで食い違う**: 別々に実装した`formatCountdown`が実装差異で90分セッションを"90:00"と"01:30:00"で別々に表示していた。`lib/countdown.js`に一本化
- **ブロック画面がセッション終了を検知しない**: カウントダウンが0になっても状態を再取得せず、解除後もブロック画面が固まったままになる問題を修正
- **オプション画面のロック/Pro制限が一部のUIに反映されない**: `querySelectorAll`の存在チェックが常にtruthyになる分岐ミスで、スケジュールの時刻入力・追加ボタンが実際には無効化されていなかった。ネイティブの`<fieldset disabled>`に置き換えて解消
- **日またぎスケジュールが日付が変わった瞬間に解除される**: 「当日の曜日」チェックのみで前日からの継続を考慮していなかった
- **スケジュールの追加/削除失敗が無言で握りつぶされる**: エラー時にステータス表示を追加
- **サイト追加/削除・スケジュール変更のrace condition**: `background.js`に`enqueue()`直列実行キューを導入し、read-modify-write競合を解消
- **セッション時間が0/NaNの場合に統計記録漏れ・セッションが永久にロックされたまま残るリスク**: `START_SESSION`にバリデーションを追加

## 実機確認(2026-08-29実施)で発見・修正した追加バグ

独立エージェントのコードレビュー(上記10件)をすり抜けた、実機でしか再現しない不具合が1件見つかった。SnapFolio同様「コードレビューだけでは検出できないクラスのバグがある」という教訓が再現した。

- **blocked.htmlのインラインスクリプトがManifest V3のCSPで無言でブロックされる**: ブロック(declarativeNetRequestのredirect)自体は正しく動くため一見正常に見えるが、`script-src 'self'`のデフォルトCSPによりインライン`<script>`の実行が全てブロックされ、カウントダウン・メッセージ書き換え・戻るボタンが機能していなかった。`blocked.js`として外部ファイル化して解決。**新規にHTMLページを追加する際は、Manifest V3ではインラインscriptを一切使わず必ず外部ファイル化すること。**

実機確認では他に、手動ブロック/集中セッション(開始・カウントダウン・セッション中ロック)/合言葉ロック(なし・誤り・正解の3パターン)/スケジュール自動ブロック/セッション自然終了時の統計記録、いずれも正常動作を確認済み(ExtensionPay未登録のためDevToolsコンソールから`isPro`フラグを直接立てて検証)。

## 多言語対応(2026-08-29実施)

Chrome拡張機能標準のi18nの仕組み(`_locales/ja`・`_locales/en`+`chrome.i18n.getMessage()`)でUI全体を日英対応。ブラウザのUI言語設定に応じて自動で切り替わるため、言語切替UIは不要。`lib/i18n.js`が`data-i18n`/`data-i18n-placeholder`属性を持つDOM要素へ自動反映するヘルパーを提供、JS側で動的生成する文言(トースト・統計文・曜日ラベル等)も`flI18n.t(key, substitutions)`経由で取得する方式に統一。`manifest.json`の`description`も`__MSG_extDescription__`化。実機でのEN切替確認はChromeのUI言語変更が必要なため、代わりにHTML/JS内で使用されている全i18nキーが`ja`/`en`両方のmessages.jsonに存在するかをスクリプトで機械チェック(不足なし)。

**教訓:** 価格(300円JPY)は据え置きでよい(Stripeは海外カードでも決済でき、$2相当は十分安い)。海外販売の実質的なボトルネックは通貨表記ではなくUI・ストア説明文の言語だった。
